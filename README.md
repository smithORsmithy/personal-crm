# Личная CRM

Контакты людей, которых я знаю лично: кто это, откуда знакомы, телефон и почта, заметки о разговорах.

## Что умеет

- Список всех контактов, отсортированный по имени
- Поиск по имени: можно вводить часть имени и слова в любом порядке, «е» и «ё» не различаются
- Добавление контакта и изменение его данных
- Карточка контакта с заметками: у каждой заметки есть дата, новые сверху. Сохранить заметку можно кнопкой или сочетанием Ctrl+Enter

Данные хранятся в базе PostgreSQL на этом компьютере, поэтому в любом браузере видны одни и те же контакты.

Продуктовая идея, главный сценарий и критерии успеха — в [specs/01-продуктовая-идея.md](specs/01-продуктовая-идея.md).

## Как запустить

Нужны Docker Desktop, Node.js 24 и pnpm.

Скачайте проект и перейдите в его папку:

```
git clone https://github.com/smithORsmithy/personal-crm.git
cd personal-crm
```

### База данных (PostgreSQL в Docker)

1. Если файла `.env` ещё нет — скопируйте `.env.example` в `.env` и заполните значения.
2. Запустите базу:

   ```
   docker compose up -d
   ```

3. Проверьте, что база работает: в колонке STATUS должно быть `healthy`.

   ```
   docker compose ps
   ```

Данные хранятся в Docker-томе `personal-crm_pgdata` и не пропадают при остановке или перезапуске.
Команда `docker compose down -v` **удаляет все данные** базы.

### Приложение: первый запуск

Все команды выполняются в папке проекта.

1. Установите зависимости:

   ```
   pnpm install
   ```

2. Создайте таблицы в базе:

   ```
   pnpm db:migrate
   ```

3. По желанию — заполните базу тестовыми данными (1000 контактов с заметками). Если в базе уже есть хотя бы один контакт, команда ничего не меняет:

   ```
   pnpm db:seed
   ```

4. Соберите и запустите приложение:

   ```
   pnpm build
   pnpm start
   ```

5. Откройте в браузере http://localhost:3000

Остановить приложение — нажать Ctrl+C в окне терминала, где оно запущено.

### Последующие запуски

Если база уже запущена (`docker compose ps` показывает `healthy`), достаточно `pnpm start`.
После изменений в коде сначала снова выполните `pnpm build`.

Для разработки удобнее `pnpm dev`: изменения в коде видны в браузере сразу, без пересборки.

## Полезные команды

- остановить базу: `docker compose stop`
- открыть консоль базы: `docker compose exec db psql -U crm -d personal_crm`
- проверить код: `pnpm lint` и `pnpm typecheck`
- после изменения схемы таблиц (`src/db/schema.ts`): `pnpm db:generate`, затем `pnpm db:migrate`

## Выкатка на сервер

Приложение работает на https://app.linkbook.site — на общем сервере с лендингом (вход: `ssh crm`).

**Как выкатить новую версию:** сделать push в `main`. Дальше всё само, обычно за 3–5 минут:

1. GitHub Actions собирает Docker-образ с тегом — номером коммита — и кладёт его в GHCR (`ghcr.io/smithorsmithy/personal-crm`).
2. Копирует папку `deploy/` на сервер и запускает там `deploy/deploy.sh`:
   - миграции базы — разовым контейнером из нового образа; если миграции упали, новая версия не запускается, старая продолжает работать;
   - запуск новой версии;
   - проверка `/health`: ответ 200 и номер нового коммита;
   - на сервере остаются только текущий и предыдущий образы.
3. Проверяет https://app.linkbook.site/health снаружи.

Ход выкатки — на GitHub: вкладка Actions → Deploy. Зелёная — новая версия работает. Красная — выкатка не удалась, видно, на каком шаге. Сама она ничего не откатывает.

**Какая версия сейчас на сервере:** https://app.linkbook.site/health — в поле `version` номер коммита.

**Откат (только вручную):** Actions → Deploy → Run workflow → в поле `image_tag` вписать полный номер нужного коммита → Run workflow. Выкатится уже собранный образ этой версии. Миграции базы при откате не отменяются.

**Тестовые данные:** Actions → Seed test data → Run workflow. Добавляет 1000 контактов только в пустую базу; если контакты уже есть — ничего не меняет.

### Что на сервере

- `/srv/crm/.env` — секреты, права 600, заполняет только человек. Одна строка: `POSTGRES_PASSWORD=<пароль базы>`. База запоминает пароль при первом запуске: позже поменять его только в `.env` недостаточно
- `/srv/crm/deploy` — скрипты выкатки, CI копирует их при каждой выкатке
- docker compose, проект `prod`: приложение `prod-app-1` (порт только на 127.0.0.1:3000) и база `prod-db-1` (без портов наружу), данные базы — в томе `prod_pgdata`
- nginx направляет app.linkbook.site на 127.0.0.1:3000; пока приложение не отвечает — заглушка с кодом 503
- пользователь `deploy-app` — от его имени CI выкатывает приложение. Ключ — в секрете `DEPLOY_SSH_KEY`, адрес и пользователь — в переменных `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` (GitHub → Settings → Secrets and variables → Actions)
- настройка сервера с нуля — `deploy/setup-server.sh`, один раз, после общей подготовки сервера из репозитория лендинга

## Где что лежит

- `src/app` — страницы: список (`page.tsx`), новый контакт, карточка и редактирование (`contacts/`)
- `src/components` — части интерфейса: список с поиском, формы контакта и заметки
- `src/lib/contacts` — чтение из базы, проверка полей и сохранение (выполняется только на сервере)
- `src/db` — схема таблиц и подключение к базе
- `drizzle` — миграции базы
- `scripts/seed.ts` — заполнение базы тестовыми данными
- `scripts/migrate.ts` — применение миграций на сервере
- `src/app/health` — проверка `/health`: приложение работает и видит базу
- `Dockerfile` — сборка образа для сервера
- `deploy/` — выкатка: compose-файл сервера, скрипты выкатки, тестовых данных и настройки сервера
- `.github/workflows/` — выкатка при push в `main` и ручное заполнение тестовыми данными
