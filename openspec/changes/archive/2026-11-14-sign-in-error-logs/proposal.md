# Proposal

## Why

Когда база данных не отвечает, ошибки входа попадают в журнал (лог — сообщения, которые приложение пишет в терминал или в `docker compose logs` на сервере) целиком, вместе со значениями из запроса: ключом сессии (по нему сервер узнаёт, кто вошёл), одноразовым ключом из ссылки в письме и почтой. Это проверено на тестовой базе: при остановленной базе одно открытие страницы пишет в журнал ключ сессии, открытие ссылки из письма — ключ ссылки. Журнал покидает сервер: при неудачной выкатке последние 50 строк журнала приложения попадают в публичный журнал GitHub Actions. Для контактов и групп это уже исправлено (`logDbError` в `src/db/log-error.ts`): в журнал идёт только текст запроса к базе, где вместо значений стоят `$1`, `$2`, и коды ошибок. Для входа так ещё не сделано.

## What Changes

- Ошибки входа пишутся в журнал так же, как ошибки контактов и групп: текст запроса к базе с `$1`, `$2` вместо значений, код ошибки (например, `ECONNREFUSED` или `EACCES` — «база не отвечает»; второй даёт Docker на Windows, когда база остановлена), имя таблицы и адрес базы. Значений из запроса в журнале нет: ни ключа сессии, ни ключа из ссылки, ни почты.
- Это касается всех мест, где вход обращается к базе:
  - проверка, кто вошёл, — перед каждой страницей и формой;
  - «Получить ссылку»;
  - открытие ссылки из письма;
  - «Выйти».
- Ошибки, которые пишет сама библиотека входа Better Auth, тоже проходят через эту очистку.
- То, что видит человек при сбое базы, не меняется: те же страницы ошибок и сообщения, что и сейчас.
- Очистка надёжнее узнаёт ошибку запроса к базе. Проверка в собранном приложении показала: при открытии страницы и при выходе текст запроса с `$1` терялся, в журнале оставался только код ошибки. Скорее всего, так же он терялся и в журнале контактов и групп на проде. Теперь текст запроса с `$1` остаётся везде, значений по-прежнему нет. Других изменений в журнале контактов и групп нет.

### Решения владельца

1. Очистку чинит эта же правка, вместе с текстом запроса для контактов и групп (вариант 1, выбран после проверки в собранном приложении).

### Решения, которые принял агент (проверьте)

1. Из журнала убираются все значения запроса к базе, а не только ключ сессии и почта. Например, адрес компьютера и название браузера, которые сохраняются при входе. Так же сделано для контактов и групп.
2. Остаётся то же, что у контактов и групп: текст запроса с `$1`, коды ошибок, имена таблицы, столбца и ограничения, адрес и порт базы. По этому можно понять, что сломалось.
3. Если библиотека входа откажет подозрительному запросу (например, пришедшему с чужого сайта), в журнале останется адрес сайта, откуда пришёл запрос. Ни ключа сессии, ни почты в нём нет, а без него не понять, откуда была попытка.
4. Дополнительные сведения, которые библиотека прикладывает к своим сообщениям (не ошибки, а, например, подробности отказа), в журнал не попадают совсем.
5. Некоторые сбои будут записаны в журнал два раза: короткой строкой библиотеки и строкой нашего кода. Обе строки без значений из запроса.

### Открытые вопросы

1. Что видит человек при сбое базы на входе, оставляю как сейчас:
   - форма «Получить ссылку» открывает страницу ошибки;
   - ссылка из письма открывает пустую страницу браузера «HTTP ERROR 500».

   Если хотите понятное сообщение, например «Не получилось отправить письмо. Попробуйте ещё раз через минуту» под формой, это отдельная правка. Её можно сделать вместе с отложенной правкой про другие сохранения при остановленной базе.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sign-in`: добавляется требование «Ошибки входа в журнале без значений из запроса» и сценарии для четырёх случаев: открыть страницу, запросить ссылку, открыть ссылку из письма, выйти — всё при остановленной базе.

## Impact

- Настройка библиотеки входа `src/lib/auth/create-auth.ts`: её сообщения идут через очистку, а ошибки страниц `/api/auth/*` отдаются нашему коду, а не пишутся библиотекой.
- Новый файл в `src/lib/auth/` для журнала библиотеки и для ответа на запросы `/api/auth/*`. Маршрут `src/app/api/auth/[...all]/route.ts` вызывает его.
- Проверка, кто вошёл: `src/lib/auth/session-check.ts`, `src/lib/auth/current-user.ts`, `src/lib/auth/proxy-answer.ts`. Ошибка, которая уходит дальше в Next.js, не несёт в себе запрос к базе со значениями.
- Запрос ссылки: `src/lib/auth/sign-in-request.ts`. Сбой подсчёта писем записывается очищенным.
- `src/db/log-error.ts`: очистку ошибки можно вызвать из других файлов. Ошибка запроса Drizzle узнаётся по её полям, а не по тому, из какой части сборки она пришла. Поля в журнале те же.
- Тесты в `src/lib/auth/*.test.ts` на тестовой базе и с базой, которая не отвечает.
- База данных не меняется, миграций нет. Новых библиотек нет.
