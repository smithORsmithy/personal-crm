# Tasks

Порядок в каждой задаче с кодом: сначала тест, запустить его и увидеть, что он красный; потом код; снова тест — зелёный. Название теста — название сценария из `specs/keep-in-touch/spec.md`. Для тестов нужны запущенные база и Mailpit: `docker compose up -d`. Решения, на которые ссылаются задачи, — в `design.md`.

Работа идёт в ветке `frequency-in-add-form`.

В задачах остаётся код: заготовки заменить настоящим кодом, тесты сделать зелёными, не ослабляя их.

## Workflow follow-up

- «Коммить и пуш» по команде владельца: коммит в ветку `frequency-in-add-form`, push, PR в main со ссылкой, автовлитие `gh pr merge --auto --squash`.
- После merge — выкатка по обычной схеме (бэкап → миграции → новый образ → `/health`), затем проверка на https://app.linkbook.site: добавить контакт с частотой и посмотреть карточку.
- Архивировать изменение (`/opsx:archive`), когда критерии приёмки выполнены.
- Отдельной мелкой правкой после этой фичи (решение владельца, решение 7 в `design.md`): остальные сохранения при недоступной базе — частота и своя дата в карточке, группы, заметки, «Изменить», удаление — тоже показывают своё сообщение вместо общей страницы ошибки, через `requireUserIdForSave()`.
